1. Introduction

The IntelliFlow AI database stores all business data required for authentication, workflows, documents, AI interactions, analytics, notifications, and auditing.

The database must be:

Normalized (up to 3NF where appropriate)
Scalable
Secure
Highly maintainable
Optimized for read and write operations
Migration-friendly
2. Database Design Principles

The schema follows these principles:

UUID primary keys
Foreign key constraints
Audit columns on every table
Soft delete support
Minimal redundancy
Indexed search fields
Snake_case naming
UTC timestamps
Strict data validation

Database Standards
UUIDs for all primary keys
UTC timestamps only
Transactions for multi-step operations
Foreign keys enforced
Indexes reviewed during performance tuning
Avoid storing AI vectors directly in PostgreSQL (keep vectors in FAISS for v1)
Use optimistic locking where concurrent updates are possible
Notes for the AI Coding Agent

When implementing the database:

Create SQLAlchemy models matching this schema.
Use Alembic for all schema changes.
Enforce constraints at both the database and application levels.
Keep models focused; business logic belongs in the service layer.
Seed default roles and permissions during the initial migration.
Add indexes only where they provide measurable benefits.
Never bypass migrations by editing the database directly.
